The Event Debugger provides visibility into your event processing pipeline, helping you track events, identify issues, and ensure accurate billing.

## Overview

When you send events to Flexprice, they go through multiple processing steps—validation, meter matching, aggregation, and billing. The Event Debugger lets you see this entire journey and quickly identify any issues.

## Accessing the Event Debugger

In the dashboard, go to **Developers → Events debugger**.

  ![Events debugger listing events with their timestamp, event name, customer ID, properties, source, and event ID](/images/docs/event-ingestion/event-debugger-1.png)

## Viewing Events

### Event Stream

The Events debugger lists the events entering your system, newest first. Click **Reload** to fetch the latest events. Each event shows:

- Timestamp
- Event (the event name)
- Customer ID (the `external_customer_id`)
- Properties
- Source
- Event ID

Use **Table options** (the **⋯** button) to hide columns or export the list as CSV.

### Event Details

Click any event, or **View event** in its **⋯** menu, to open its details: the event ID, source, customer ID and the Flexprice customer it matched, the idempotency key, and the properties.

**What happened to this event** traces the event through processing: whether it was ingested, matched a customer, matched a meter, found a price, landed on a live contract, and was counted towards usage. Expand **Response** under a check to see the data behind it. If the event wasn't counted, the first failed check shows why.

<Frame>
  ![Event details panel with the processing checks for an api_call event](/images/docs/event-ingestion/event_details.png)
</Frame>

The raw event looks like this:

```json
{
  "id": "event_01",
  "external_customer_id": "cust-new",
  "event_name": "api_calls",
  "timestamp": "2025-10-15T11:38:47.962Z",
  "properties": {},
  "source": "onboarding",
  "environment_id": "env_10"
}
```

## Sorting Events

Click the **Sort** button to order events by **Time**, ascending or descending. The list starts with the newest events.

## Filtering Events

Type in **Search by event name** to show only the events with that name.

Use the **Filter** button to narrow the list further. Click **Add filter** and pick a field:

- **Customer ID**: events sent for one `external_customer_id`, such as `cust_new`
- **Source**: events from one source, such as `onboarding`

Both match the exact value, and you can combine several filters. The dashboard has no event ID or time filter: the API's event query (`POST /v1/events/query`) filters by event ID, time range, and event properties as well.

## Common Use Cases

### Verify Events Are Being Received

After setting up event ingestion, check the Event Debugger to confirm events are arriving:

1. Navigate to the Events Debugger
2. Look for your recent events in the list
3. Click on an event to view its full details

### Debug Missing Events

If expected events aren't showing up:

1. Check that `event_name` matches your metered feature exactly
2. Verify `external_customer_id` is correct
3. Confirm the timestamp is RFC 3339 with a timezone, such as `2026-10-10T14:03:00Z`
4. Check the source parameter matches your expected value

### Find Events for a Specific Customer

To review all events for a customer:

1. Click the **Filter** button
2. Click **Add filter**, choose **Customer ID**, and enter the customer's external ID

### Review Events in a Time Period

The dashboard lists events newest first, so recent periods are at the top. Sort by **Time** ascending to start from the oldest. For an exact date range, query the API (`POST /v1/events/query`) with `start_time` and `end_time`.

## Best Practices

**Test Event Integration Early**
Send test events and verify they appear in the debugger before going to production.

**Monitor Regularly**
Check the debugger periodically to ensure events are being received correctly.

**Verify After Changes**
After updating metered features or plans, use the debugger to confirm events still process correctly.

**Use Filters Effectively**
Combine multiple filters to quickly find specific events you need to review.
