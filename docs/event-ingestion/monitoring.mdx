---
title: "Event Monitoring"
description: "Monitor the health and performance of your event ingestion and processing pipeline"
---

The Event Monitoring endpoint helps you track event ingestion and processing in real-time, allowing you to identify bottlenecks and ensure events are flowing correctly through your system.

## API Endpoint

```
GET https://api.cloud.flexprice.io/v1/events/monitoring
```

### Authentication

Include your API key in the request header:

```
x-api-key: <your_api_key>
```

### Request Parameters

All query parameters are optional. With none, the endpoint covers the last 24 hours of data for your tenant and environment.

| Parameter | Description |
|-----------|-------------|
| `start_time` | Start of the period, as an RFC 3339 timestamp. Send it together with `end_time`, or leave both out. |
| `end_time` | End of the period, as an RFC 3339 timestamp. Send it together with `start_time`, or leave both out. |
| `window_size` | Splits the event count into time buckets returned in `points`: `MINUTE`, `15MIN`, `30MIN`, `HOUR`, `3HOUR`, `6HOUR`, `12HOUR`, `DAY`, `WEEK` or `MONTH`. Leave it out to get only the total. |

Sending only one of `start_time` and `end_time` returns `400`.

### Response

```json
{
  "total_count": 15432,
  "consumption_lag": 245,
  "post_processing_lag": 78
}
```

**Response Fields:**

- `total_count` - Total distinct events stored in ClickHouse in the requested period (the last 24 hours by default)
- `consumption_lag` - Kafka consumer lag for event processing (number of unprocessed messages)
- `post_processing_lag` - Kafka consumer lag for feature usage tracking (number of unprocessed messages)
- `points` - Present when `window_size` is set: one entry per bucket, each with a `timestamp` and an `event_count`
