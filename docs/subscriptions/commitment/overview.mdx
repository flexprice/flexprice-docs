Commitment-based pricing is a billing model that lets customers commit to a minimum spend or quantity for each billing period. It gives the business predictable revenue and lets the customer pay for actual usage beyond the commitment at a defined overage rate.

A legacy commitment has one of two scopes. A **contract commitment** is one minimum shared by all of a contract's usage charges. A **line-item commitment** is a minimum on a single usage charge. Both scopes are configured through deprecated API fields and bill different sets of charges. The dashboard now adds [subscription commitments](/docs/subscriptions/commitment/subscription-commitments) through the **Commitments** section.

| | Contract commitment | Line-item commitment |
|---|---|---|
| **Covers** | All usage charges on the contract, added together | One usage charge |
| **Commits to** | A spend amount | A spend amount or a number of units |
| **Dashboard** | Not available for new legacy commitments | Existing charge commitments are read-only |
| **API** | `commitment_amount`, `overage_factor`, and `enable_true_up` on the subscription | `line_item_commitments`, keyed by price ID |
| **True-up** | Billed as a separate line item | Added to the charge's own line item |
| **Time-of-day buckets** | Not supported | Supported |

A contract uses one scope or the other. Flexprice rejects a contract commitment combined with a line-item commitment, with the message "Use either subscription-level commitment or line-item-level commitment, not both".

<Warning>
  The commitment fields on this page are deprecated: `commitment_amount`, `commitment_duration`, `overage_factor` and `enable_true_up` on subscription create, `line_item_commitments` on subscription create and addon attach, and the `commitment_*` fields on line items. Flexprice still accepts them, so existing integrations keep working, but new commitments should use [subscription commitments](/docs/subscriptions/commitment/subscription-commitments), created with `POST /commitments`. Subscription commitments are available in every environment, with no setting to turn on.

  A subscription can't mix the two on the same charges. Flexprice refuses a subscription commitment over a line item that has a legacy commitment, legacy commitment fields on a line item a subscription commitment covers, a subscription commitment on a subscription with a contract commitment, and a create request that sends both.
</Warning>

<Note>
  This page covers legacy contract and line-item commitments. To pool a commitment across several prices, stack reservations, set separate committed and overage prices, or collect a commitment through upfront and scheduled payments, use [subscription commitments](/docs/subscriptions/commitment/subscription-commitments) with [billing terms](/docs/subscriptions/commitment/billing-terms).
</Note>

## How Commitment Works

Both scopes apply the same rule:

1. **Commitment amount**: The minimum the customer commits to per billing period (e.g. \$1,000/month). This guarantees the revenue floor. A line-item commitment can be a number of units instead, which Flexprice converts to an amount at the charge's price.
2. **Overage factor**: A multiplier applied to usage cost above the commitment (e.g. 1.5x). When usage exceeds the commitment, the excess is billed at the overage rate.
3. **Usage calculation**:
   - If total usage cost ≤ commitment: all usage is charged at the base rate.
   - If total usage cost > commitment: the commitment portion is charged at the base rate, and the excess is charged at `base_rate × overage_factor`.

The usage cost is the total of every usage charge for a contract commitment, and the cost of one charge for a line-item commitment.

## Contract Commitment

A contract commitment sets one minimum spend for the whole contract. Flexprice adds up the cost of every usage charge on the contract and applies the commitment to that total. Fixed charges, such as a platform fee, don't count toward it and are never billed at the overage rate. To set a minimum on one charge instead, use a [line-item commitment](#line-item-commitment).

<Warning>
  A contract commitment takes effect only when the **Overage factor** is greater than 1. At the default of 1, Flexprice bills usage at the normal rate and adds no true-up.
</Warning>

### Steps to Add a Contract Commitment

Set this legacy scope through the API using the deprecated `commitment_amount`, `commitment_duration`, `overage_factor` and `enable_true_up` fields on subscription create. For new dashboard commitments, use the **Commitments** section as described in [Subscription Commitments](/docs/subscriptions/commitment/subscription-commitments).

## Line-Item Commitment

A line-item commitment sets a minimum on one usage charge. Only that charge's usage counts toward it, and only that charge is billed at the overage rate. The contract's other charges bill at their normal rates. Each usage charge can carry its own commitment, and an [add-on's](/docs/product-catalogue/addons/add-to-subscription) usage charges take one the same way.

### Steps to Add a Line-Item Commitment

Set this legacy scope through the API using deprecated `line_item_commitments`, keyed by price ID, on subscription create or add-on attach, or the `commitment_*` fields on line items. The dashboard no longer offers commitment actions on charges or add-ons. Existing charge commitments remain visible read-only on the contract. For new commitments, use [Subscription Commitments](/docs/subscriptions/commitment/subscription-commitments).

## Understanding True-Up

True-up ensures the customer pays the full commitment even when actual usage falls short. Both scopes support it.

### How True-Up Works

1. **During the billing period**: Flexprice tracks usage and computes the running usage cost.
2. **At invoice generation**:
   - Usage cost < commitment AND true-up enabled: Flexprice bills the shortfall. A contract commitment adds it as a separate line item named after the plan, such as **Developer True Up**. A line-item commitment adds it to that charge's line item, which then bills the full commitment.
   - Usage cost ≥ commitment: standard commitment-and-overage logic applies, and no true-up is needed.

### Steps to Add True-Up

For legacy commitments, set `enable_true_up` through the API with the [contract commitment](#steps-to-add-a-contract-commitment) or [line-item commitment](#steps-to-add-a-line-item-commitment) fields. These deprecated fields are no longer configured in the dashboard. For new dashboard commitments, use **Binding** in the **Commitments** section; see [Subscription Commitments](/docs/subscriptions/commitment/subscription-commitments).

## Time-of-Day Commitment Buckets

A line-item commitment applies for all 24 hours of the day. If you need different commitments and prices for different parts of the day, for example reserved capacity from 09:00 to 17:00 UTC and standard pricing outside it, configure [time-of-day buckets](/docs/subscriptions/commitment/time-of-day-buckets) on the line item. Configure legacy buckets through the deprecated API fields on the line item. For new dashboard commitments, use **Measured over** and **Active windows (UTC)** in the **Commitments** section; see [Subscription Commitments](/docs/subscriptions/commitment/subscription-commitments). Contract commitments don't support buckets.
